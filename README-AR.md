# Impact Tech — Portfolio 1.0

مشروع PHP Laravel 12 + Blade، بواجهة عربية RTL ولوحة تحكم، مع SQLite افتراضيًا وإمكانية استخدام MySQL. لا يحتاج إلى بناء JavaScript أو Node على الاستضافة.

## ما يتضمنه
- صفحة شركة متجاوبة: خدمات، مشاريع، نبذة، ونموذج تواصل يحفظ الطلبات داخل لوحة التحكم.
- إدارة الخدمات والمشاريع: إضافة، تعديل، حذف، ترتيب، مسودة أو نشر.
- رفع صور المشاريع والشعار (PNG/JPEG/WebP)، وتعديل اللون الرئيسي والنصوص وبيانات التواصل ووصف SEO.
- دراسات حالة: المشكلة، الحل، الخدمات، التقنيات والنتيجة، مع تصفية الأعمال حسب التصنيف.
- تسجيل دخول مسؤول، حماية صلاحيات وCSRF، تحديد محاولات الدخول وطلبات النموذج، والتحقق من الصور والروابط.
- عرض طلبات التواصل وتحديث حالتها؛ لا يرسل النظام بريدًا تلقائيًا.

## حالة التسليم
كود مصدر مكتوب، وليس موقعًا منشورًا. لم يمكن تشغيل PHP أو Composer في بيئة الإنشاء؛ لذلك لم تُنفّذ اختبارات Laravel ولم تُتحقق الصور بصريًا في المتصفح. يجب تثبيت الاعتماديات وتنفيذ الاختبارات أدناه على بيئة PHP قبل النشر. مجلد vendor وملف composer.lock غير مرفقين؛ أول تثبيت يحل الاعتماديات، ثم يجب الاحتفاظ بملف القفل الناتج في المستودع.

## التثبيت لأول مرة
يتطلب PHP 8.2 أو أحدث وComposer وإضافات Laravel المعتادة، بما فيها PDO SQLite وMbstring وXML وFileinfo وGD لاختبار رفع الصور. مرجع متطلبات الاستضافة: https://laravel.com/docs/12.x/deployment

نفّذ من جذر المشروع:

```bash
composer install
cp .env.example .env
php artisan key:generate
```

أنشئ ملفًا فارغًا باسم `database/database.sqlite`، ثم نفّذ:

```bash
php artisan migrate --seed
php artisan storage:link
php artisan impact:admin your-email@example.com
php artisan serve
```

أدخل بريد المسؤول الحقيقي مكان المثال. ستطلب الأداة كلمة مرور مخفية بطول 12 حرفًا على الأقل؛ لا توجد كلمة مرور افتراضية أو صفحة تسجيل عامة. افتح الموقع على http://localhost:8000 ولوحة الإدارة على http://localhost:8000/admin.

لتغيير كلمة مرور المسؤول من السيرفر:

```bash
php artisan impact:password your-email@example.com
```

## الاختبار قبل النشر

```bash
composer test
php artisan route:list
php artisan view:cache
```

اختبارات مرفقة للتحقق من منع الزائر وغير المسؤول، إخفاء المسودات، حفظ المشروع ورفع الصورة وحذفها، تسجيل الدخول والخروج، رفض روابط JavaScript، والتحقق من طلبات التواصل. اختبر يدويًا على كمبيوتر وموبايل: تعديل النصوص، نشر خدمة، رفع شعار وصورة، حفظ مشروع، نموذج التواصل. عند فشل اعتماديات Composer، عالج المتطلب المفقود؛ لا تستخدم تجاهل متطلبات المنصة.

## النشر على الاستضافة
- اجعل document root يشير إلى مجلد `public` فقط. لا تعرض جذر المشروع أو `.env` أو قاعدة البيانات للويب.
- اضبط APP_ENV=production وAPP_DEBUG=false وAPP_URL على النطاق الحقيقي وSESSION_SECURE_COOKIE=true مع HTTPS.
- امنح خدمة الويب صلاحية الكتابة إلى storage وbootstrap/cache، وإلى database عند استخدام SQLite.
- نفّذ composer install --no-dev --optimize-autoloader ثم php artisan migrate --force وphp artisan storage:link وphp artisan optimize.
- لتفعيل MySQL: عدّل DB_CONNECTION=mysql وأضف DB_HOST وDB_PORT وDB_DATABASE وDB_USERNAME وDB_PASSWORD قبل ترحيل الجداول.
- انسخ قاعدة البيانات وstorage/app/public احتياطيًا بانتظام. احتفظ بـ APP_KEY؛ لا تولّده مجددًا بعد بدء الاستخدام.
- خطا IBM Plex Sans Arabic وSpace Grotesk يُطلبان من Google Fonts مع خطوط نظام بديلة عند تعذر التحميل.

## استخدام لوحة التحكم بدون كود
1. افتح «المحتوى والهوية» وأدخل الشعار ووسائل التواصل المعتمدة والعنوان والنبذة واللون.
2. راجع «الخدمات». الخدمات التي ذكرتموها منشورة مبدئيًا؛ ربط الأنظمة وصفحات الهبوط والصيانة مسودات مقترحة لا تظهر حتى اعتمادها.
3. افتح «المشاريع» ثم «إضافة مشروع» وأدخل المعلومات والصورة، وحدد «نشر في الموقع» عند اكتماله.
4. عدّل رقم الترتيب: الأصغر يظهر أولًا.
5. راجع «طلبات التواصل» وحدّث كل طلب إلى «تم التواصل» أو «مغلق».

## المحتوى المعتمد والناقص
لم تُختلق مشاريع أو عملاء أو نتائج أو أرقام خبرة. لا توجد مشاريع مزروعة؛ القسم يعرض دعوة لمناقشة المشروع حتى إضافة أعمال حقيقية. لم يمكن استخراج محتوى الموقعين أثناء الإعداد. الألوان والشعار النصي اتجاه تصميم مقترح؛ يضاف الشعار الرسمي وبيانات الشركة من لوحة التحكم. يلزم اعتماد الخدمات المقترحة وإضافة المشاريع الفعلية ووسائل التواصل قبل النشر العام.

## سجل العمل
- المنجز: بنية Laravel، واجهة الشركة، لوحة إدارة، رفع صور، طلبات التواصل، اختبارات مكتوبة، ودليل تشغيل.
- الحالي: تسليم المصدر للمراجعة؛ التشغيل والتحقق على PHP لم ينجزا في بيئة الإنشاء.
- التالي: تثبيت المشروع واختباره على استضافة PHP، إضافة الهوية والأعمال المعتمدة، ثم نشره على النطاق المطلوب.
